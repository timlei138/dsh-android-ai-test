# 用例够不够格跑

**10 秒，心算，不要写脚本、不要读文件、不要调研。**

---

## 判断方法

在脑子里过两个问题：

### ① 有步骤吗 —— 知道要做什么吗

能不能按顺序说出「先做什么、再做什么」。

```
✅ 「点右上角更多 → 选那个入口 → 点里面的第一项」
✅ 「走A-走B」
❌ 「测一下那个新功能」      → 做什么？不知道
```

### ② 有预期吗 —— 做完该看到什么，说得出来吗

**这是关键。** 每条预期要能落成一句「看到 X 就算过」。

```
✅ 「点「导入」→ 预期：进入选图页」
   → 能不能看到：前台切到选图页
   → 反证：没反应 / 弹别的

✅ 「点「完成」→ 预期：保存成功并回到列表页」
   → 能不能看到：页面变了
   → 反证：停在原地 / 报错

❌ 「界面显示正常」   → 什么算不正常？
❌ 「功能可用」       → 可用是什么样？
```

**更细一点的预期要好，但不是必须**：

```
好  「A 页面有「添加课程」标题，B 页面表单有 5 个字段」
可以「进入 A 页面，点 B 弹窗，弹窗里能改名称和颜色」
```

**说得出「什么算 FAIL」就够格，不必写到控件的粒度。**

## 三条会拦。其他都放行

### ⛔ 没有预期

```
「跑一下 168」  ← 但对话里从来没给过预期
→ 不派，问用户："这条要验什么？做完该看到什么？"
```

### ⛔ 预期说不出反证

```
❌ 「界面正常」「功能可用」「体验良好」
→ 不派，问："「正常」具体指看到什么？"
```

### ⛔ 超出工具层能力（只能看屏幕，管不了硬件）

**工具层能做的只有：看屏幕、点按、输入、滑动、读文字。**

预期落在下面这些上的，**不派**，直接告诉用户「这条现在跑不了」：

```
❌ 声音   响铃 / 提示音 / 震动有没有响
❌ 连接   蓝牙、WiFi、蜂窝、NFC 的配对与连接
❌ 硬件   充电、电量、温度；光线、距离等传感器读数
❌ 成像   摄像头拍出来的画质（能进相机界面，判不了成什么样）
❌ 性能   帧率、内存、启动耗时
```

**例外：横竖屏不拦。** 虽然物理上转不了设备，但可以用命令模拟：

```
adb shell settings put system accelerometer_rotation 0   # 关掉自动旋转
adb shell settings put system user_rotation 1             # 横屏（0 为竖屏）
```

用例步骤里出现「切换到横屏」「横屏模式下打开」这类，子 Agent 用上面的命令做就行，
「横屏下显示正常」这类预期照样可判（看屏幕就是了）。不拦，放行。

### ⛔ 本机造不出来

```
❌ 需要另一台设备做对端（蓝牙配对、跨设备同步）
❌ 需要真实网络账号（登录态、云端数据）
❌ 需要特定硬件（NFC、指纹模组）

✅ 「已有 XX」不算 —— 子 Agent 会现场做
✅ 需要清数据、重启 App 不算
```

---

## 其余情况一律放行

**不要因为下面这些拦：**

```
❌ 步骤写得糙、没分点
❌ 预期只有一句话
❌ 一条预期里含两件事（含就含，派发时提醒子 Agent 逐件核对就行）
❌ 步骤数和预期数对不上（差几条很正常）
❌ 前提和步骤看起来有点矛盾（子 Agent 会现场处理）
❌ 不知道这功能在哪、怎么点
❌ 不确定能不能做成
```

**这些都不是"不许跑"的理由 —— 那是子 Agent 要解决的问题，不是你的。**

## 用例从哪来

### 用例文件在哪（直接读文件，**不要查数据库**）

```
D:\Project\deepseek\android-ai-test-skills\assets\cases\<应用包名>\
    <应用包名>_<功能>_<编号>.md          ← 原始用例（人写的）
    <同名>_steps.yaml                    ← 跑过之后沉淀的跳转步骤（有就比 .md 更准）
```

**同一条用例，`_steps.yaml` 优先** —— 它是从同名 md 那条用例跑出来的，带上次实测的落点。
没 `_steps.yaml` 就用 `.md`。

列出某应用全部用例，一条命令：

```powershell
dir "D:\Project\deepseek\android-ai-test-skills\assets\cases\com.zui.calendar"
```

**不要查 `sessions.db`** —— 那是运行记录，不是用例库。
用户问"有哪些用例"→ 看目录；问"跑过几次/上次什么结论"→ 那才查库。

### ⚠️ 敲 shell 命令之前，先看 env

**本机不一定是 Linux。** 第一条命令先跑这个：

```
python D:\Project\deepseek\android-ai-test-skills\tools\env.py
```

它告诉你 `shell` 是 bash 还是 powershell。**只看一次，整个会话都按那个来。**

实测踩过：问「有多少 case」，第一条就发

```
ls -1 "D:/Project/deepseek/android-ai-test-skills/assets/cases"
```

**Windows PowerShell 的 `ls` 不认 `-1`，直接 exit 1。**

如果是 powershell，改成：

```
dir "D:\Project\deepseek\android-ai-test-skills\assets\cases"
```

> 但 `adb shell "..."` 里的内容永远是 Android 的 Linux，不用改。

### 用户在对话里直接贴了用例

```
用户：「跑 176。这是用例：步骤 1... 2... 预期 1... 2...」
→ 就用这段（**它比文件里的新**，用户可能刚改过）

用户：「跑 176」（没贴，但文件里有）
→ 读 assets/cases/<应用>/com.zui.calendar_176.{yaml,md}

用户：「跑 176」（文件里也没有）
→ 问："176 的步骤和预期是什么？"
```

**用户贴的优先级最高** —— 他刚说的就是最新的。

## 派发

过关就派，一行命令：

```
subagent(
  agent_preset = "android-executor",
  description  = "执行用例 <编号>",
  prompt       = "..."
)
```

**`prompt` 里放：**

```
1. 用例原文（原样贴，一个字都不改）
2. 设备 serial：51e8bf1c
3. 被测包名
4. 工具层路径：D:\Project\deepseek\android-ai-test-skills
5. 你的提醒（如果有）：比如"第3条预期含两件事，逐件核对"
```

**`prompt` 里不放：**

```
❌ 你拆好的步骤
❌ "先做 A 再做 B" 的方法指导
❌ 历史跑过几次
❌ 你猜的技术方案
```

**为什么原样贴**：子 Agent 的 SKILL 要求它按预期逐条记
`finding --expect "<预期N>" --actual "<看到的>"`。
你把原文改了，它记的预期就对不上用户的原话了。

---

## 报人时说什么

说清：**缺什么** + **怎么补**。

```
❌ 不派发。

这段只有步骤没有预期：
  「点右上角更多 → 选那个入口 → 点里面的第一项」

做完这串该看到什么？比如「进入选图页」。

你说清这个，我就能派。
```

**不要自己编预期填进去** —— 编出来的预期是假的，
跑出假 PASS 比报"判不了"更糟。

---

## 派完之后

子 Agent 回来什么就说什么，**不要润色**：

| 状态 | 你说什么 |
|---|---|
| **PASS** | "验过了，3 条预期都符合" |
| **FAIL** | "发现不符合预期的行为：<哪条>" |
| **BLOCKED** | "**没验成**" ⚠️ 不能说成功能有问题 |
| **PAUSED** | "在等你回答：<它的原话>" |

## 回看执行记录（Web UI）

用户想看「这轮到底怎么跑的、每步什么画面、哪条断言挂了」，用 Web UI：

```powershell
cd <工具层目录>
.venv\Scripts\python.exe webui.py
```

打开它给出的地址，能看到：

| 看什么 | 在哪 |
|---|---|
| 每条用例的执行记录 | 首页列表 |
| 逐事件耗时 | 记录详情页 |
| 每一步的截图 / dump | 点进具体步骤 |
| 断言与证据的对应 | 记录详情页的 finding 区 |

**什么时候主动提 Web UI：**
- 用户问「刚才怎么跑的」「为什么这么久」
- 用户要看截图但你没拿到（子 Agent 只回了文字结论）
- 用户想对比两次跑的差别

**工具层目录** = 插件的 `target` 配置值（含 `.venv` / `tools` / `assets` / `storage` 的那个）。

> 别自己去 sqlite 里翻 `events` / `findings` 表 —— 那是工具层的存储格式，
> 用 Web UI 看更直接，也不会看错。
