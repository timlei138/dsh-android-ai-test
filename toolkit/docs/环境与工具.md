# 环境搭建与工具全参数

> SKILL.md 的附录。**只在首次搭建环境、或需要查某个参数时读**，日常执行用不到。

## 环境搭建（一次性）

### 一键安装（推荐）

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
```

依次做：检查 adb → 检查设备 → 建 venv 装依赖 → 初始化 uiautomator2 → 自检。

| 参数 | 用途 |
|---|---|
| `-SkipDeviceCheck` | 没插设备也先装依赖 |
| `-Recreate` | 重建已存在的 venv（venv 被占用时会给出提示） |
| `-SkipDeps` | 只建 venv，不装依赖 |
| `-Python <路径>` | 显式指定解释器 |

### 手动安装

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
adb devices -l                              # 设备在线且已授权
.venv\Scripts\python -m uiautomator2 init   # 设备端初始化（每台设备一次）
```

### Python 版本：3.10+（**没有上限**，3.13 也可以）

| 边界 | 原因 |
|---|---|
| **≥3.10** | `pillow` 12 起要求 `>=3.10`（3.9 装不上新版 pillow） |
| ~~≤3.12~~ | **这个上限已经取消** —— 见下 |

**为什么以前有上限**：OCR 库旧名 `rapidocr-onnxruntime` 停更在 1.2.3，
元数据写死 `requires_python="<3.13"`，所以 3.13 上装不了。

**现在没有上限**：该库改名成 **`rapidocr`**（3.x），原生支持 3.13。
本机验证过的组合：**Python 3.13.3 + rapidocr 3.10.0 + onnxruntime 1.31.0**。

`setup.ps1` 会自动挑出合格解释器；也可用 `py -0p` 看本机装了哪些。

## 工具清单

**动设备、看屏幕、读文件，一律走 `android_*` 工具。只有 `session.py` 用 bash。**

| 工具 | 干什么 | 常用参数 |
|---|---|---|
| `android_env` | 环境探测（开工第一条） | 无 |
| `android_observe` | 看一屏：activity + 可点清单 + 截图 | `full` `noFilter` |
| `android_act` | 动手：tap / longclick / input / swipe / back / home / key | 见下 |
| `android_read` | **OCR，只读文字** | `image` `region` |
| `android_vision` | **视觉模型，读图标/颜色/布局** | `image` `prompt` `max_tokens` |
| `android_read_file` | 读知识卡 / 路径卡 / 任意文本 | `card` `path` `query` `section` `grep` |
| `android_perm` | 查 / 授 / 撤权限（走 adb，不走弹窗） | `package` `grant` `revoke` |
| `android_state` | 清数据 / 起停 App / 权限预置 | `action` `package` `perm` `activity` |
| `android_system` | 系统级界面：通知栏 / 快捷设置 / 亮屏解锁 / 横竖屏切换 | `action` `close` `to` |

> 参数是**结构化 JSON**，不走 shell 解析 —— 中文、弯引号、空格、等号、
> **空字符串**都能原样传进去。

## 各工具参数

### android_env

不需要参数。返回 25 个字段，平时只需要看这几个：

| 字段 | 内容 |
|---|---|
| `platform` / `shell` / `path_sep` | 宿主平台、shell 类型、路径分隔符 |
| `storage_dir` | 产物落点（工具层根目录 `tool_root` = 它的上一级） |
| `deps_ok` | 依赖装好没有（`ok` / 缺哪个包） |
| `writability` | `{storage, run_history, tmp, knowledge, cases}` 五个目录，**空串=可写**，非空=写不进去的原因 |
| `storage_writable` / `assets_writable` | 上面两项的汇总布尔值 |
| `device` | `{serial, ime, ime_ok, advice}` —— 设备在不在线、输入法就绪没 |
| `shell_exe` | 每次 `android_*` 调用实际用的 shell 解释器 `{path, kind, version, slow, advice}`；`kind=powershell5` 时 `slow=true`（每次多约 1.4 秒） |
| `workspace` / `workspace_confidence` | 会话工作区路径与判定置信度（`high` / `low`） |
| `storage_source` | storage 目录是怎么定出来的 |

其余字段（`python` / `tools_dir` / `record_dir` / `tmp_output` / `knowledge_dir` / `tmp_dir` /
`hint` / `tool_root` / `tool_root_in_workspace` / `storage_in_workspace` / `roots_agree` /
`root_note`）是排障辅助，正常不用看。

`deps_ok` 不是 `ok`、或 `writability` 里有一项不是空串 → **环境跑不起来**，先照 `hint` /
`root_note` 修好再往下走。

`ime_ok: false` 表示当前输入法不是 `com.github.uiautomator/.AdbKeyboard`，
照 `advice` 那条命令切回来；否则打字会报
`ADB_KEYBOARD_CLEAR_TEXT failed`，容易被误读成「控件坏了」。

### android_act

| 参数 | 说明 |
|---|---|
| `action` | `tap` / `longclick` / `input` / `swipe` / `back` / `home` / `key` |
| `x` `y` | 坐标，从**上一次返回**的 `next[].c` 取（禁止复用旧坐标） |
| `via` | 定位依据（坐标从哪个元素推出来），路径图采集靠它 |
| `why` | 这一步的理由（时间轴展示）；back/home/key 也支持 |
| `expect` | 检查点，声明「这一步之后应在哪」；命中与否由工具判 |
| `text` | `input` 的文本。**传 `""` = 清空输入框** |
| `append` | `input` 时追加而不是覆盖（默认覆盖） |
| `from` / `to` / `dur` | `swipe` 的起终点与毫秒 |
| `code` | `key` 的 Android keycode |
| `repeat` / `gap` | `tap` 连点 N 次、间隔毫秒（**只有 tap 支持**） |
| `settle` | 动作后稳定窗口毫秒，默认 500 |
| `permAction` / `perm` | 声明权限意图（测拒绝路径时才用） |
| `full` | nodes 给全量语义节点（默认 nav：只给可点/可滑动节点） |
| `serial` | 多设备时指定 |
| `name` | 证据名，缺省自动派生 `<会话id>/step<N>` |

执行动作 → 稳定窗口 → **自动再做一次 observe**，一个调用回传「动作 + 动作后画面」。

> ⚠️ `tap` / `longclick` **必须给 `x` `y`**，没有 text/desc/id 选择器。
> 传 `text` / `id` / `desc` 会直接参数报错（不会执行）。
> 理由：`t`（text）定位在同 rid 多态时不可靠（一个 `android:id/button1`
> 可能是"删除/完成/确定"），坐标由本次 dump 现场派生才准。

> ⚠️ `back` / `home` / `key` 不接受 `via` / `x` / `y` —— 它们不点屏幕。

> ⚠️ 滚动列表用 `swipe`；**拨滚轮类控件**（日期/时间选择器）别用 `swipe` ——
> 有惯性会过冲，用 `tap` + `repeat N`。

### android_observe

| 参数 | 说明 |
|---|---|
| `full` | 全量语义节点 |
| `noFilter` | 不过滤非前台包的节点（状态栏/导航栏/桌面 taskbar 噪音） |
| `name` / `serial` | 证据名 / 设备 |

一次给：前台包名 + activity + 旋转 + 可点清单 `next` + 截图 + `dump.xml` 落盘。

**什么时候用**：① 会话第一步 ② 上一步的 `next`/`nodes` 里找不到目标。
其余情况一律从前一步 `android_act` 的返回里读 —— 每步多一次 observe 就是多一次往返。

### android_read —— OCR

| 参数 | 说明 |
|---|---|
| `image` | 指定已存在的截图；不传则现场截一张 |
| `region` | `x1,y1,x2,y2`，只保留中心落在该矩形内的行 |
| `name` / `serial` | 证据名 / 设备 |

读 UI 树里没有的东西：toast、Canvas 自绘文字。返回文本 + center 坐标
（`center` 可直接给 `android_act` 的 `x`/`y`）。
toast 是浮层会消失，act 之后尽快 read。
`region` 是筛结果不是裁图 —— 全图仍整张跑 OCR，只是把返回收窄，耗时不变。

> OCR **认不了图标**（加号/对勾/颜色）—— 那类问题用 `android_vision`。

### android_vision —— 视觉模型

| 参数 | 说明 |
|---|---|
| `image` | 图片路径（绝对路径或相对工具层根） |
| `prompt` | 要问什么。**要具体、可判**（「有没有加号」→ 答有/没有） |
| `max_tokens` | 回答长度上限，默认 2000 |

用在：图标在不在、按钮是不是灰的、布局怎么排的。
**不要用它做 OCR 的活**（读文字用 `android_read`，快且准）。

> ⚠️ 提问要封闭：「这个按钮是不是灰色不可点？」而不是「描述一下这个界面」——
> 开放描述题会让模型回长文，一次能吃掉 84 秒。

### android_read_file

| 参数 | 说明 |
|---|---|
| `card` | 包名。**同时搜知识卡 + 路径卡**，结果按 `[知识卡]` / `[路径卡]` 标注 |
| `path` | 单个文件或目录（目录会列条目） |
| `query` | 自然语言检索（分词 + 同义词 + 标题加权） |
| `section` | **数组**，按小节读：`section=["A", "B"]` 一次读完多节 |
| `grep` | 精确子串匹配（找 rid / 文案），返回命中行及上下文 |
| `offset` / `limit` | 按行读（1-based，默认 120 行） |

超 **8000 字符**会截断。

> ⚠️ 别用 `path=` 整份读知识卡 —— 整卡上万字，读两次就把上下文挤满了。
> 用 `card=` + `query` / `section` / `grep`。

### android_perm —— 权限

| 参数 | 说明 |
|---|---|
| `package` | 包名（必填） |
| `grant` / `revoke` | 要授/撤的权限；不传就只查 |
| `serial` | 多设备时指定 |

短名会自动补 `android.permission.` 前缀：
`camera` / `location` / `mic` / `contacts` / `storage` / `media_images` /
`notifications` / `READ_CALENDAR` / `POST_NOTIFICATIONS` …

特权权限（`READ_PRIVILEGED_PHONE_STATE` 这类）授不了，会报
「is managed by role」—— 那是系统限制，不是用例失败。

> **只在弹窗根本不出现时用**：act 的 tap/longclick 已经会自动点掉权限弹窗。

### android_state —— 设备状态原语

| `action` | 额外参数 | 作用 |
|---|---|---|
| `clear` | `package` | ⚠️ 清空应用全部数据 |
| `start` | `package` + `activity` | 起 App |
| `stop` | `package` | 停 App |
| `grant` | `package` + `perm` | 预置已授权 |
| `revoke` | `package` + `perm` | 预置未授权 |

短名同 `android_perm`。

> **只在用例明确要求时用**：用例写「首次使用」「清理数据」才 clear；
> 测「已授权/已拒绝」路径时用 grant/revoke 预置状态。
> 用例没写清理 → 什么都不做（清理不是收尾动作）。

### android_system —— 系统级界面

| `action` | 额外参数 | 作用 |
|---|---|---|
| `notifications` | `close` | 展开通知栏，**并解析出通知列表** |
| `quick_settings` | `close` | 展开快捷设置面板 |
| `close_shade` | — | 收起通知栏 / 快捷设置 |
| `wake` | — | 点亮屏幕 |
| `unlock` | — | 点亮并解锁 |
| `rotate` | `to` | 切换横竖屏，**返回切换前后的宽高**（`to`=`portrait`/`landscape`/`toggle`，默认 `toggle`） |

| 参数 | 说明 |
|---|---|
| `action` | 必填，见上表 |
| `close` | 拍完证据后顺手收起面板（`notifications` / `quick_settings` 用） |
| `expect` | 检查点，命中与否由工具判（同 `android_act`） |
| `settle` / `name` / `serial` / `full` | 同 `android_act` |

**为什么不能自己 `swipe` 下拉**：手势要求起点贴最顶端、速度有讲究、坐标随分辨率变，
历史上有 9 个会话出现「再试一次拉下通知栏」。这里内部走 uiautomator2 的 jsonrpc
（`openNotification()`），**43 毫秒**，而 `swipe` 要 1,567 毫秒。

**返回里怎么读**：

| 字段 | 说明 |
|---|---|
| `applied` | **动作生效了没有**，三态：`true` / `false` / `null` |
| `applied_note` | `applied` 为 `null` 或 `false` 时说明原因 |
| `notifications[]` | 通知列表 `{title, texts, clickable, bounds, center, rid}` |
| `notification_count` | 解析出的条目数 |
| `rows_detected` | 有没有认出「真通知行」（`expandableNotificationRow`） |
| `shade_note` | 解析不出内容时的说明 |
| `shade_kind` | 展开的是 `notifications` 还是 `quick_settings` |
| `shade_controls` | 面板上的按钮（如「静音」「历史记录｜管理」） |

- `applied: true` → 继续。
- `applied: false` → 没生效。先 `action="unlock"` 再试，**同一步最多 2 次**，还不通记 BLOCKED。
- `applied: null` → **工具证实不了**（拿不到 `window_size` 时 `rotate` 才会这样）。**看截图判断，不要重试** —— 重试不会让判断更清楚。

`rotate` 是唯一自带实测证据的动作，返回：

```json
"rotate": {
  "before": {"width": 1904, "height": 3040, "orientation": "portrait"},
  "after":  {"width": 3040, "height": 1904, "orientation": "landscape", "changed": true},
  "changed": true,
  "requested": "landscape"
}
```

`changed: false` = 命令发了但尺寸没变（工具会如实报，不谎报成功）。

> 底层是 `cmd window user-rotation lock <0|1>`（0=竖、1=横）。
> **`settings put system user_rotation` 不可靠** —— 它只写设置，要等下一次旋转事件才生效。
> 另注意这台机上 `d.rotation` 是坏的（AttributeError），横向判定一律看 `window_size`。

> ⚠️ `rows_detected: false` 且 `notifications` 为空，**不等于没有通知** ——
> 可能是这个 ROM 换了行 id。看 `shade_note` 和截图，别据此判「没有提醒」。

> ⚠️ **分组通知只算 1 条**：几条提醒被系统折叠成一个分组时，`notification_count`
> 算的是分组卡（1 条），不是里面的条目数。要精确判某条提醒，先
> `tap` 那张卡的 `center` 展开，再 `android_observe` 看逐条。

> ⚠️ 展开的通知栏会挡住后续操作，用完记得 `action="close_shade"`
> 或直接 `action="notifications", close=true` 看一眼顺手收掉。

## session.py —— 唯一用 bash 的

开会话、记断言、收尾必须走 bash（它要读口述用例、写库）。**必须带 `&` 前缀**：

```powershell
& "<target>\.venv\Scripts\python.exe" "<target>\tools\session.py" <子命令> ...
```

| 子命令 | 说明 |
|---|---|
| `start --title --input [--case <id>] [--device] [--package] [--related] [--diag]` | 开会话 |
| `finding --status --expect --actual [--event-id <ID>] [--note] [--id]` | 记断言；PASS/FAIL 必须绑定证据，多个 ID 重复传参 |
| `findings-batch --file <json>` | **一次写完所有断言**（逐条调每次间隔约 6 秒） |
| `finish --status --summary [--package] [--id]` | 收尾写结论 |
| `resume --id --note` | 崩溃终止后人工确认继续（清除终态，必须给理由） |
| `perm-intent --action grant\|deny [--perm] [--clear\|--show]` | 声明权限响应意图（**不声明默认 grant**；测拒绝路径时才用） |
| `case add/list/show/update/save` | 用例库维护 |
| `paths [--id]` | 采集路径边 → 生成待确认草稿 `storage/pending_paths.md`（`finish` 时已自动做） |
| `paths-apply [--only 1,3]` | 把草稿写入路径图 |
| `list` / `current` | 查看会话 / 看当前指针 |
| `abandon --id --reason` | **作废**一个还在跑的会话：写终态（正常进 `ERROR`，被崩溃终止过的进 `BLOCKED`）+ 解绑指针；已是结论态的只解绑、**不覆盖**已写结论 |

要点：

- **中文长文本用 `@文件` 传参**（`--input @case.txt`，UTF-8）——命令行直传中文
  在部分终端管道里会被 GBK 双重解码；expect/actual/summary 同理。
- finding 的 expect/actual 必须是**具体判据**（dump 字段值 / OCR 文本），不能只写"正常"。
- 从观察/动作/OCR 返回的 `event_ids` 显式选取支持断言的事件；跨会话、无证据或证据文件不存在的引用被拒绝。BLOCKED/ERROR 可不带验证证据，但 actual 必须说明原因。
- `finish` 校验通过后才事务提交结论和用例统计；拒绝或写入失败退出码 1，保留当前会话。PASS 只允许 PASS findings；FAIL 必须存在 FAIL finding。BLOCKED/ERROR 必须有 summary 原因。
- 历史记录只补结构，不自动伪造证据关联。未完成会话若存在无证据断言，不能以 PASS/FAIL 提交，需核实后以 ERROR/BLOCKED 说明原因收尾。
- 证据绑定不代表模型判断正确，也不能证明原始用例预期全部覆盖，须逐项审计。正式完成的会话不能再次 finish。
- **正式用例进用例库**：首次跑通后 `case save --session <N> --last` 提升
  （`--last` 在「上一次已收尾的运行」里找这个会话，**`finish` 之后入库必须加，否则找不到库**）；
  复跑 `start --case <id>` 自动带出标题与文本。
- **验证/调试跑动加 `--diag`**：工具自检、探针验证等非正式测试的会话，不进「测试记录」库、不计入仪表盘成功率。
- **开场自动准备输入法**：`start` 连上设备后会调 uiautomator2 的 `set_input_ime(True)`，
  把 `com.github.uiautomator/.AdbKeyboard` 装上并设为默认输入法。结果写在 `note` 里。
  设失败不影响建会话。
- **用例结束自动采集路径边**：`finish` 时把「落脚点 → 锚点 → 去向」采成**待确认草稿**
  `storage/pending_paths.md`（**不看会话结论**，FAIL/BLOCKED 里走过的路径也有效）。

### 耗时怎么看

每个工具执行完会把自己的耗时写进数据库的 `events.duration_ms`：

```powershell
sqlite3 "<target>\storage\test.db" "select sum(duration_ms) from events"
```

或者直接看 webui 的记录详情页。

| 字段 | 范围 |
|---|---|
| `duration_ms`（事件） | 核心操作区间：连接完成后至采集、签名与崩溃检查完成；OCR 包含导入/初始化、图像获取与结果转换。均不包含初始连接、事件写入、节点返回构建与序列化；不是完整 CLI 墙钟时间 |
| `timing.process_observed_ms` | 从 runtime 模块载入开始，到生成该快照；更早导入与进程启动不在此区间 |
| `timing.stages_ms` | 实测阶段：设备导入/连接、动作、等待、权限、采集、崩溃检测及取证、节点处理、记录、序列化、OCR 导入/初始化/推理/图像信息/结果转换；未出现的阶段不是零 |
| `response_bytes` | stdout UTF-8 字节数，包含换行；不等于模型 token 数 |

默认模型可见返回不带 timing；诊断时可设置 `ANDROID_TEST_VERBOSE_TIMING=1` 展开返回。
不能把不同快照相加；crash_evidence 是 crash_detection 的子区间，不能重复累计。

### 回归隔离

可指定绝对存储目录（不要指向正在使用的目录）：

```powershell
$env:ANDROID_TEST_STORAGE = "D:\TestArtifacts\android-baseline"
```

数据库、当前会话、默认证据、崩溃指纹、计时、路径草稿、cleanup 清理范围及 vision 配置
使用该目录。应用知识卡是共享资产（`assets/knowledge/`），**不受这个变量影响**；
`paths-apply` 写的是 `assets/knowledge/paths/` 下的**路径卡**，也不动知识卡。

### 记录不完整

工具执行中出现记录失败会写标记到 `storage/recording_errors/<session_id>/`，
后续设备调用被拦截，禁止重放；该会话只允许以 ERROR/BLOCKED 并说明原因收尾。

## 环境问题排查

### `android_env` 报 `deps_ok` 不是 ok

说明 venv 里缺包。进工具层根目录：

```powershell
.venv\Scripts\pip install -r requirements.txt
```

> ⚠️ **不要用 PATH 里的 `python`** —— 那是系统解释器，大概率没装
> `uiautomator2`/`adbutils`。工具层自己永远走 `<target>\.venv\Scripts\python.exe`，
> 只有你手动 bash 时才可能踩这个坑。

### `android_env` 报 `device.serial` 为 null

`adb devices` 确认设备是 `device` 态（不是 `offline` / `unauthorized`）。
没授权就在手机上点「允许」。多台设备才需要显式传 `serial`。

### 命令写法：看 `android_env` 报的 `shell`

**不要假设平台，也不要自己去探测 —— 工具已经探好了。**

按 `shell` 决定辅助命令的写法：

| `shell` | 怎么写 |
|---|---|
| `bash` / `zsh` | `ls -la`、`head -20`、`&&`、`2>/dev/null`、`/tmp` 随便用 |
| `powershell` | 见下面那张对照表 |
| `unknown` | 先用最简单的写法试一条，看它成不成，再决定 |

> ⚠️ 只有 `session.py` 和辅助命令走 shell。`android_*` 工具是结构化调用，
> 不存在 shell 转义问题 —— 这是它们比命令行脚本强的核心原因。

### `shell` 是 powershell 时

Windows 的 PowerShell 5.1 缺一些 bash 惯用工具：

| bash 习惯 | PowerShell 替代 |
|---|---|
| `ls -la dir` | `Get-ChildItem dir` / `dir dir`（别名不认 `-la`）|
| `head -20 f` | `Get-Content f -TotalCount 20` |
| `tail -50 f` | `Get-Content f -Tail 50` |
| `grep -r x .` | `Select-String -Path * -Pattern "x"` |
| `cmd1 && cmd2` | `cmd1; cmd2`，或 `if ($?) { }` |
| `cmd 2>/dev/null` | `cmd 2>$null` |
| `cmd \| head` | `cmd \| Select-Object -First 20` |
| `sed -n '1,20p' f` | `Get-Content f -TotalCount 20` |
| `which x` | `Get-Command x` |
| `/tmp/x` | `$env:TEMP\x` |
| `export A=1` | `$env:A = "1"` |

**必须带 `&`** —— 调 exe 不加 `&`，PowerShell 会当成字符串报 `Unexpected token`。
**读 UTF-8 文本加 `-Encoding utf8`** —— 不加会按 GBK 读成乱码。

以 `env.shell` 为准，别看到 "win32" 就一律换掉 ——
有些 Windows 环境装了 Git Bash 或 WSL，`ls -la` 反而能用。

### 唯一不需要看 `env.shell` 的例外

`adb shell "..."` **里面的内容永远是 Android 的 Linux**，与宿主平台无关：

```bash
# ✅ 一定对（不管你在 Windows 还是 Linux 上跑）
adb -s <serial> shell "dumpsys window | grep mCurrentFocus"

# ❌ 这个 grep 在宿主上跑，要看探测结果
adb devices | grep 51e8
```

记法：**引号里给手机跑的永远是 Linux；引号外给宿主的，看探测结果。**

## 维护脚本

这些是**人工维护用**的，不是测试执行路径。

### logcat.py —— 崩溃取证

```powershell
& "<target>\.venv\Scripts\python.exe" "<target>\tools\logcat.py" --serial <s> crash [--package com.app] [--tail 500] [--raw]
& "<target>\.venv\Scripts\python.exe" "<target>\tools\logcat.py" --serial <s> clear
& "<target>\.venv\Scripts\python.exe" "<target>\tools\logcat.py" --serial <s> setup   # logcat -G 5M（session start 自动做）
```

> `--serial` 与子命令位置两种写法都支持。

### cleanup.py —— 证据轮转

```powershell
& "<target>\.venv\Scripts\python.exe" "<target>\tools\cleanup.py" --days 7 [--dry]
```

删除 7 天前的 `evidence/` 与 `logs/`。每步 act/observe 都落全分辨率截图，定期跑。

### webui.py —— Web 测试台

```powershell
& "<target>\.venv\Scripts\python.exe" "<target>\webui.py" [--port 8900]
```

`webui.py` 在**工具层根目录**，不在 `tools/` 下。默认端口 **8900**。

查看会话时间线、截图证据、用例库、知识库、仪表盘。
⚠️ 绑定非回环地址会警告（无鉴权，知识库 POST 可被同网段改写）。

### run.py —— 用 venv 解释器跑任意工具脚本

```powershell
& "<target>\.venv\Scripts\python.exe" "<target>\tools\run.py" <脚本> [参数...]
```

它做三件事：找 venv 解释器 · 强制 UTF-8 · 原样转发参数并透传退出码。
日常执行用不到（走 `android_*` 工具就够了），只在排查工具层本身时用。
