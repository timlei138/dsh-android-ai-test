- **app**: `_system`（兜底卡，不可删除）
- 适用场景：权限弹窗、系统对话框、BACK 键、通知栏、应用通知开关、预装应用管理、Toast、三段式滚轮选择器

## 权限弹窗

- **工具会自动点**，不用你管。默认点「同意」。
- **媒体类权限（拍照 / 相机 / 图片 / 相册 / 视频）走「两阶段」固定规则**：同一类权限
  **第一次弹框自动点普通「拒绝」**（拒绝不改授权状态，框下次还会来），**第二次弹框自动点
  「允许」**。进度按弹框的申请文案记在会话上，跨步骤有效；不需要 AI 判断，也不需要声明意图。
- 其它权限（通知、定位、联系人等）**不做两阶段**：拒一次就可能再也不弹，自动拒会把同意
  分支彻底堵死，所以默认直接允许。要测它们的拒绝分支才显式声明 `permAction="deny"`。
- 权限相关用例**必须先测拒绝分支、再测同意分支**：拒绝只是让权限保持未授予，
  不影响下次再弹；反过来先同意的话，权限变成已授予，**弹框不会再出现**，
  后面那条"选择拒绝"就无从验证了。
- 永远不要点「拒绝并不再询问」——点了这个权限的弹框永不再出现，同意分支就没了。
  工具在「只剩这一个拒绝项」时会主动放弃并标 `unmatched`，此时先 revoke 权限再重触发。

## BACK 键

- 有输入法弹出时，**第一次 BACK 只收键盘，页面完全不动**；再按一次才回退页面。
- 所以用 BACK 回退之前必须先确认键盘状态，否则两种翻车：以为收了其实没收到（多按一次 = 多退一级），或者以为没收到其实已收（按一次就把页面退掉了、丢了未保存的编辑）。
- 更稳的做法是不依赖 BACK，点页面自身的关闭/完成锚点，或点空白处收键盘。

## 预装应用

- **恢复已卸载的预装应用，唯一固定入口是：设置 → 应用管理 → 恢复预装应用 → 选中目标应用 → 恢复。** 不要另找路径。
- 恢复成功的表现：该应用重新出现在「所有应用」列表，且同一行的按钮由「恢复」变成「打开」。
- 「用系统命令能装回预装包」是误解：那条路只对**被禁用**的包有效，对**已经真正卸载**的包会报找不到。带销毁性的卸载用例，兜底必须走「恢复预装应用」界面。
- 判断一个应用是否支持卸载：**长按桌面或应用列表里的图标，看菜单里有没有「卸载」**。有就能卸（便签、日历），没有就不能（系统「设置」只有小部件/应用信息）。
- 「查询包是否安装」在系统侧是**子串匹配**，会把 `包名.overlay.*` 这类主题包一起命中 —— 拿它判"装没装"会永远为真，进而让卸载检测恒为假、兜底恢复永不触发。必须按整行精确比对。

## Toast

- Toast 是屏幕上的浮层文字，出现后约 **1~2 秒**自动消失。它不属于任何页面，不改变 activity。
- 它不一定出现在 UI 树里，通常只能靠读屏文字确认。
- 因此必须在触发动作之后**立刻**去看，隔一步再找就没了。
- 读不清（字小、被遮挡、背景花）时问视觉模型。

## 通知栏

- 通知**左右横滑 = 划掉（删除）**，该通知从通知栏消失。
- 通知**上下竖滑 = 展开**露出操作按钮，或再收回一行，通知仍然在。
- 用例说「收起通知」指的是收起面板或把卡片收回去；横滑是删除，通知会直接没了，**不是收起**。
- 同一应用的多条通知会被系统按分组**折叠成一个组卡片**，卡上显示「N 项活动」和拼接的条目名。组内条目默认不直接可见，点开组卡片才展开逐条。
- 有分组时，**横滑组内任意一条，整组（含汇总条）会一起消失**。后面的步骤如果还要点这条通知，横滑完就没得点了，只能重建数据 —— 先看后面还用不用它，再决定滑不滑。
- 顶部悬浮横幅（heads-up）是提醒触发瞬间从顶部弹出的，停留约 **1.7 秒**，截晚了就没有了。
- 要在横幅上做动作（滑动/点按钮）必须**在触发前就准备好**，触发后立刻动。
- 横幅没抓到**不能判为失败**，可以退一层判断"通知栏里有这条通知"。
- 用例写「滑动提醒弹窗」时要先分清指的是顶部横幅还是通知栏里的卡片 —— 两者能做的动作不一样。

## 应用通知开关：两个层级

系统设置里搜应用名能进到该应用的「应用通知」页，这里有两个层级，动错了结论就反了：

- **应用级总开关**：关掉之后该应用**完全不发通知**。
- **单个通知类别**：把某个类别改成「静音」，通知**照发**，只是不出声、不振动。

按用例措辞选层级：

```
用例说「关闭通知 / 没有通知」 → 动应用级总开关
用例说「静音 / 不要声音」     → 动单个通知类别
```

判据是：改完再触发一次，**通知栏里有没有这条通知** —— 有就是有，没有就是没有。
在类别上做静音，然后把"通知照旧出现"判成"没有通知"，是判错了层级。

## 弹窗还是整页：按视觉判，不看页面标识

- 一个界面「看起来是浮在别的东西上面」还是「占满了整个屏幕」，与它在系统里是怎么实现的**没有对应关系**：
  浮层卡片也可以是一个完整的独立页面，整页也可以是同一个页面里叠出来的。
- 所以判「弹窗 / 整页」只看**视觉**：周围有没有被压暗或半透明的背景、下面那层界面还看不看得见、
  关掉之后是不是回到刚才那一屏。看得见下面的内容就是浮层，铺满全屏看不到别的内容就是整页。
- 页面标识（activity 名、类名、路由）**只能说明"到了哪个界面"，不能用来判它是弹窗还是整页**。
  拿它下这个结论会判错方向，进而把步骤和结论一起带偏。
- 同一个功能从"弹窗"还是"整页"进入，视觉可以完全不一样，但它们可能就是同一个界面 ——
  先按视觉描述写在用例里的那种形态去核对，不要用实现上的名字反驳用例的措辞。

## 涉及日期时间等修改，并且是标准三段式滚轮形式

- 形态：一列数字上下排列，**中间一行高亮**是当前值，上下行是相邻档。
- **优先用 `tap` 拨，不要用 `swipe`**；要点多格就加 `repeat`，一次点够：
  `tap(x,y,repeat=N)` = 连点 N 下。**不要用滑动去"估距离"** —— 滑多远走几格并不确定，
  过冲之后还要反向找回来，越调越乱。
- 点**高亮行正上方** = −1，正**下方** = +1，点高亮行本身 = 不变。
- 弹框上下边缘是**死带**，离高亮行越远越不可靠。第一下先点一格确认方向，再连拨。
- ⚠️ **方向不保证统一**：同一个 App 里，不同弹框的方向可能相反。每次都要先试一格。
- **同款弹框在不同页面会上下平移**，照搬上次的坐标会"点了没反应"。
- 档位通常**双向循环**：拨到头继续拨会回到另一端。验证上下限就是"拨到回绕"，不用数总数。
- 拨完必须用截图/OCR 或视觉模型确认当前值，**不能靠"拨了几次"推算**；漏读时不要反复读
  OCR，按格数继续拨、点确定，再用读屏读得到的字段做判据。

## 判定界面归属

- 判断"是否进入了某个界面"，看**当前前台 activity**，不要用界面上的文字去猜 —— 同一个界面在不同入口下文案可能不同，而 activity 是确定的。
- 弹窗消失、回到原应用，是"点掉弹窗"成功的一般表现。

## 窗口尺寸变化有过渡帧，布局判定看静置态

- 浮窗缩放、分屏比例调整、横竖屏 / 全屏切换之后，界面有约 1~2 秒的过渡动画；动作刚结束时看到的画面和读到的视图树都是**过渡帧**，控件位置、文字截断、临时叠压都可能与稳定态不同。
- 过渡帧上的「重叠 / 截断 / 闪屏」不能当判定依据：过渡残影会随动画结束消失，只有静置后仍在的才算稳定态问题。
- 区分方法：同一操作后看两帧 —— 动作后即抓一帧、静置 2~3 秒后再抓一帧；两帧不一致按过渡残影处理，**以静置帧为判定基准**，视图树坐标核对也用静置帧。


## 判定证据只用语义锚点，不用坐标/分辨率

- 点击操作用坐标是工具接口的设计（`tap` 只接受 x/y），但**坐标、像素、bounds、分辨率 / window_size 都不能当判定证据**。
- 判据只认语义锚点：`activity`（到了哪个界面）、`rid`（控件语义 id）、界面文字 / OCR、截图的视觉现象。
- 原因：坐标和分辨率随设备型号、横竖屏、分屏、字体缩放改变。换设备后按旧坐标点的检查点会整片落空，
  那是证据失效，不是功能回归；反复问图确认「点到哪了」只会拖慢用例，还容易判错。
- 判断「是否进入某界面」看 `activity`（见前面「判定界面归属」）；判断某控件 / 文字是否存在看 `rid` / OCR。
