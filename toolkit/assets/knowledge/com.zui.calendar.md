## 首次启动会连弹三个框

清除应用数据后首次启动，按固定顺序连弹三个，全部处理完才到主页。不知道这条会以为"主页打不开 / 更多找不到"：

1. **应用自己的权限说明框**「日历需要使用以下权限」——按必要/可选分组列出权限，底部是「退出 / 同意」。
   框出现后约 1.5 秒内点「同意」会**点空**（入场动画还没结束），要等动画结束再点，点完确认框已消失。
2. **系统权限弹窗**——一次申请多个权限，在同一个框里换文案连续问，全部问完才关闭（详见 `_system.md`）。
3. **课程表功能引导框**「课程表上新了！」——触发时机是**清数据后首次启动、在日历主页上弹**，
   **不是**"进入课程表功能的时候"。

> 这三个只在清数据后出现，之后再冷启动都不会有（本地已记"看过"）。
> 反过来说：用例没提清数据就不要顺手清 —— 每清一次，后面每条用例都要重走这三连。

## 课程表：空态与加号

- 空格子本身是可点的占位，**没有加号**。
- **进入空课表时，所有格子都只有占位、没有任何加号**；点某一个格子之后，**那个格子**才出现加号。
- 加号是图形，没有文字也没有描述，读屏读不出来，只能靠位置或截图判断。
- 再点加号进入新建课程页。

## 添加 / 编辑课程：视觉是弹窗，实现是页面

这是本 App 最容易判错的一处：**实现上是一个独立 Activity，视觉上却是浮层弹窗** ——
圆角卡片压在周视图上、背景压暗、下面的课表还看得见、关闭后回到原处。

所以：用例说「弹出编辑弹窗」时要按**视觉**判（浮层 = 弹窗），不要拿 activity 名判成"跳到了整页"。

「新建课程」和「编辑课程」是**同一个界面**，区别只在于编辑态多一个「删除课程」按钮。

- 字段：课程名（必填）/ 教室 / 备注（老师）/ 课程时间（默认"第1节"）/ 上课周数（默认"第1-20周"）/ 背景色
- 「课程背景色」点开是**另一个独立弹框**，里面是 **10 个纯色块**，色块无文字无描述
- ⚠️ 数色块要看图：读屏树里可点节点会被嵌套和装饰干扰，数出来的个数远大于 10（会数成 25），
  必须看截图数
- 整个表单在本机型**一屏内放得下**：读不到某字段时先滚回顶部再向下找（双向），
  不要默认"在下面"就无脑上滑 —— 会把本来可见的元素滚出屏幕，越滚越找不到

## 时间选择弹窗全部是 Canvas 绘制的

日期、时间、时长、周数这类选择弹窗（滚轮、日历、日期选择）**都是 Canvas 画的**，
控件不在读屏树里 —— 认不出、也读不到值。只能靠**截图文字识别或视觉模型**来判断"当前值是多少"。

由此带来两个后果：

- 拨动之后的"现在值是几"必须用 OCR / 视觉确认，不能靠"我拨了几次"推算
- OCR 在弹框内会偶发漏读（返回空）。漏读时**不要靠反复读 OCR 反馈来收敛**，
  否则会在循环上绕圈、走满上限还在原地。按档位次数点、点确定，再用读屏能读到的字段做最终判据

## 滚轮怎么动

- 点滚轮**偏上** = 值 −1，点**选中行** = 不变，点**偏下** = 值 +1。
- 太靠近弹框上下边缘是**死带**，点了完全不变。
- ⚠️ 方向可能因弹框而异 —— 月视图的日期弹框与新建事件页的弹框方向相反，第一次用先试探一格。
- **同款弹框在不同页面会上下平移**，可点区域跟着平移。照搬上一次的位置会"点了没反应"，
  很容易误以为是滚轮不响应而去改用滑动，结果过冲更难收敛。
- 滚轮是**双向循环**的：上课时长档位 30…120（每档 5），拨到 120 再往下 → 回到 30；
  课间休息档位 5…30（每档 5），5 再往上 → 30。方向统一是**上=减小、下=增大**。

## 事件不在 App 自己的数据里（两层存储）

- 日历**事件不在 `com.zui.calendar` 的数据目录**，由系统组件 `com.android.providers.calendar` 承载。
- 因此**清除日历应用自己的数据不会删掉任何事件**，只重置应用设置
  （会出现上面的首次启动三连、「抢火车票」回到暂不显示、「每周起始日」回到星期一）。
- 想让 provider 归零要清 provider 的数据；但**日历界面读的不完全是这一层** ——
  会出现"provider 查得 0 条、界面仍显示事件"，因为界面走的是自带同步缓存。
- **启动日历就会触发一次云同步回灌**：只要启动应用就会把事件插回来，停止同步和强制停止都拦不住。
  不启动应用时，清 provider 的结果才能稳定保持。
- 关联账户是联想账号体系，日历账户名显示为 `PC Sync`。

## provider 只认「日程」，别的分类都不在里面

新建事件页左侧的分类**不是同一套存储**：

| 分类 | provider 里能查到？ |
|---|---|
| 日程 | ✅ |
| 提醒 / 课程 / 倒数日 / 生日 / 纪念日 | ❌ 存应用内部库 |

**后果**：拿 provider 当"保存是否成功"的判据，会把提醒/课程/生日/倒数日/纪念日的正常保存
全部判成"没落库"。这是**方法错**，不是产品缺陷。

要看这些分类存没存上，走**纵览表**（主页「更多」→「纵览」，左侧是分类，右侧列出该分类条目）。
⚠️ 纵览表停在搜索态时，左侧点分类不生效（右侧仍是上次的搜索结果），先退出搜索态。

## ⭐ 提醒什么时候会响：触发时刻 = 开始时间 − 偏移

**这是造"等提醒"类数据的前提，算错就白造。**

```
触发时刻 = 事件开始时间 − 提醒偏移
  偏移可选：任务发生时(0) / 5分钟前 / 15分钟前 / 30分钟前
  日程分类的默认值是「15分钟前」

例：事件设 10:19，提醒「15分钟前」→ 触发时刻 = 10:04
```

**要"等一会儿再响"，反推开始时间**：先拿设备当前时间（不要用本机时间，可能校时跳变），
开始时间 = 当前时间 + 偏移 + 操作余量（至少 5 分钟），建事件时就设成这个值。

⚠️ **触发点已经过去的事件，保存当时不会立即弹出提醒。**
（旧说法「触发点已过 → 保存瞬间就弹」不成立：保存了一个开始时间已过去 2 分钟的事件，
保存后立刻看通知栏——日历一条都没有；直到几十分钟后另一个提醒触发时它才一起出现。）
所以：**触发点已过不能用来"立刻造出一条提醒"**；也不要因为"保存后没弹"就判提醒没注册。

## 「提醒到了没有」看通知栏，不看 alarm 表

提醒到了，用户看到的就是**通知栏里多出一条**。这是唯一对用户可见的判据。

- 通知栏里的通知可以左右横滑删除、上下竖滑展开（详见 `_system.md`）。
- 同一 App 的多条通知会被系统折叠成一个**组卡片**，卡上写「N 项活动」和拼接的条目名。
  所以「通知栏里有几条日历通知」数出来是**组卡片数**，不是条目数；要逐条看得先点开分组。
- 结构化的旁证：系统通知记录里能看到每条通知的标题（`android.title`）。

> ❌ **不要用 alarm（系统闹钟/调度表）判断"提醒有没有生效"** ——
> 触发过的条目会从表里消失，查不到不代表没生效；表里有一条也不代表用户收到了通知。
> alarm 只在**造数据阶段**有用：确认"闹钟排在未来的某个时刻"，判断的是"我设的时间对不对"。

**三种会白做的情形**：

```
① 开始时间设成现在或过去 → 触发点已过 → 保存后根本不弹，等也等不到
② 用了默认「15分钟前」，但开始时间只比现在晚 10 分钟 → 触发点同样是过去
③ 触发点已过就去 alarm 表里查不到 → 断定"没注册" → 白重建一遍
```

**但"到点了通知没来"也可能是被测行为本身**：如果用例要求「先结束进程、再等提醒」，
进程被杀后闹钟可能随之取消、通知自然不来 —— 这是**被测结果**，不是造数据失败。
判 PASS / FAIL 看用例怎么写的，别急着重造。

## 强制停止会连带取消闹钟，只结束后台进程不会

验证「结束后台运行后提醒仍能到达」这类用例时，两种"结束"的语义完全不同：

- **强制停止**（把应用置为禁用态）：连同**已注册的闹钟一并取消** → 这类用例不能用它，太严厉
- **只结束后台进程**：应用仍是"已启用"，**闹钟保留** → 这才是用例说的「结束后台运行」

用强制停止后，闹钟会被移除并在系统记录里留下 `pi_cancelled` 的痕迹 ——
**这才是"提醒没来"的真正原因**，不是应用缺陷。
而且强制停止后应用处于禁用态，**下次手动启动前闹钟和广播都不会送达**，要恢复得先启动一次。

## 通知栏展开会挡住后续操作

上一条用例结束在**通知栏展开**状态时，下一条的第一步会打在通知栏上而**完全无效**：
界面归属仍是通知栏（`NotificationShade`），页面上什么都没变。

- 判据：当前焦点是 `NotificationShade` 而不是应用自己的页面
- 收起方式见 `_system.md`；注意**不要用"再拉一次通知栏"去收起**，连拉两次仍然是展开的

## 判据口径与已知缺陷

### 必填校验不是置灰，是点下去被拦住

规格常写"名称为空时完成按钮置灰"，**实际不置灰**：按钮的 enabled / clickable 都是 true，
点下去才被校验拦住（页面停在原页、没有提示）。

- 日历的"置灰"是**整体变淡**的画法，读屏树里 `enabled` / `clickable` 可能**不变**，
  所以置灰断言要以**截图**为准，不能靠读 enabled 字段下结论。

### 自定义结束时间那一行点了没反应（已知缺陷）

重复结束页里：

- 「永不结束」默认是**勾选**的，此时自定义结束时间的日期是灰色不可用
- 取消勾选后该行文字和日期**变黑**，界面认为可交互了
- ⚠️ **但那一行点了没有任何反应**：读屏树里容器是 clickable，换多个位置点都一样，
  activity 不变、不弹框、节点无变化；系统日志显示触摸**已投递到应用**且无异常
  ⇒ 是点击被应用吃掉，不是没点到
- 附带：该日期默认值是 2024年1月1日，早于当前日期，初始值本身不合理

### 多选态的置灰规则

进入多选态后出现「设为当前」「删除」两个按钮，**置灰看 enabled 字段**：

| 勾选情况 | 设为当前 | 删除 |
|---|---|---|
| 只勾当前课程表 | 置灰 | 可用 |
| 勾选多个（含当前） | 置灰 | 可用 |
| 只勾非当前课程表 | 可用 | 可用 |

即：**勾选集合里含"当前课程表" → 设为当前置灰**。另外新建的课表**不会自动抢占"当前"**。
⚠️ 删除弹框文案是「确定删除**此**课程表吗？」，与课程卡片的「确定删除**此**课程吗？」不同。

### 删除全部课程表后有"两种空"

| 时机 | 落点 | 三个按钮 |
|---|---|---|
| 删光的**当场** | 列表空态「没有课程表」+「点击 + 创建新课程表」 | 没有 |
| **离开再回来** | 引导式空状态页「还未添加课程表」 | 三个都在 |

删光后列表页**不会自动跳转**，要离开再回来才回到引导式空状态页。

### 月视图「票」标记的位置

抢火车票设置生效后，月视图日期格**右上角**会出现一个小「票」字，整屏文字识别能读出 `票`。

⚠️ **「票」在格子右上角，日期数字在格子中偏左 —— 两者横向不对齐**，
直接用「票」的横向位置去认日期会错位。要用点击回验（点日期格后确认落在哪一天）再换算。

### 一键备份的提示不区分有没有内容

即使一条事件都没有，点「一键备份」也会提示「备份成功」。
这个提示在有内容 / 没内容时文案一样，**不能当"确实备份了数据"的判据**。

### 不在当前视口的元素读不到内容

列表/表单里**不在当前视口内的元素读出来是空字符串**，直接判会连报失败。要滚到可见再读。

⚠️ 尤其注意顺序：课程时间页的**节行时间会随「上课时长 / 课间休息」实时重算** ——
先把时长拨到 30 分钟，所有节行就变成 30 分钟制，此时再读原始时间已经不是原值了。
要断言"默认时间显示"，必须在改时长**之前**采集快照。
